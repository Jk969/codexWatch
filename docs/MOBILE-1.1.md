1.1.2 修正真实日志确认的 CLI 恢复失败：`exec resume` 不支持 `--color`，去掉该参数并使用 JSON 事件等待 `turn.started` 后再确认发送。启动失败返回错误，草稿保留。历史详情解析不再广播 `item` 或历史完成通知，避免重复旧消息和误触发待发队列；增量读取按完整行原始字节更新偏移，防止尾部空行多计一个字节或中文半行丢失。滚动跟随依据插入消息前的位置。安装包版本号 1.1.2 / versionCode 5。

1.1.1 修正远程设备消息调用未定义的 `renderTab`、设备离线错误回执缺少 `ref`、安卓旧连接回调覆盖新连接状态和服务退出后页面状态未同步的问题。发送前同时检查原生 socket 状态与目标设备在线状态，断线立即结束等待并保留草稿。新增原生桥模式经真实中继发送纯文字及离线回执测试；真实安卓异常场景仍需真机复核。

- 输入区左侧“＋”可选择图片或文件。安卓使用系统选择器，不申请全盘存储权限；支持多选、预览和移除。每条消息最多 5 个附件，单个附件不超过 20 MB。
- 附件经现有实时通道分片发送到目标电脑，成功收到每片确认后继续上传，复用业务帧路由，没有新增云端上传接口。文件保存在电脑的 `~/.codex/codexwatch/attachments`。图片 PNG/JPEG/WebP 用 `localImage` 或 CLI `--image` 输入；普通文件附带电脑路径供 Codex 读取。文件内容明确标为资料。HEIC 等格式可作为文件上传，不自动转换为图片输入。
- 发送失败保留文字和附件供重试；聊天返回后保留当前进程内草稿。附件并非云存储，电脑服务重启后未发送附件须重传。
- 模型与思考强度常驻输入区。模型列表、支持档位、默认值来自目标电脑的 `model/list`，与账号和 CLI 配置一致，接口依据 [OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。模型点选后用于下一条消息，思考档位用中文滑杆展示，并可恢复模型默认值。
- 系统返回键及全面屏返回手势先关闭菜单，再关闭最上层子面板、聊天；首页才切到桌面。Android 13 及以上注册系统返回回调，旧版使用 Activity 返回入口。输入法和系统文件选择器由系统处理返回。
- Bridge 先占用本机端口再启动云连接，同端口的重复启动直接退出，避免同一设备的多份进程互相踢下线。
- 新版 Bridge 使用 `X-CodexWatch-Protocol: 2` 握手头。中继保留已在线的新版连接，拒绝旧协议重复进程抢占；旧连接退出不再错误广播新版设备离线。修复中继把 WebSocket 客户端 Set 当作键值对遍历的心跳异常。云端更新前备份为 `/root/codexwatch/relay/index.js.backup-20261009-mobile11`。

聊天文本开放原生长按自由选区，覆盖用户消息、Markdown 正文/代码/表格、思考与工具内容，按钮不可选。选区存在时延后完整快照和 item_refresh 的 DOM 替换，增量消息不强制滚动；取消选区后按保留的浏览位置刷新。approval-selection-test.js 验证协议参数、失败状态、废弃模式拒绝、不可控桌面请求拒绝、中文任意片段和实时更新选区保护、320px 布局；目录与消息同步测试同时通过。浏览器测试不替代安卓真机系统选区手柄和复制菜单。版本 1.2.8 / versionCode 16。协议参考：https://learn.chatgpt.com/docs/app-server 。

1.2.7：真实日志确认手机的 `send_message_to_thread` 投递记录为 `response_item.function_call_output`，带 `codex_app` 命名空间、接口名与 `codex_delegation` 封装，不是普通 user 消息。解析器仅针对这类结构恢复用户气泡，去掉手机转发提示前缀并标明来源，使用原始 item ID 对 response_item 和 item_completed 双记录去重；普通工具输出不能冒充用户。历史重放、重复增量、压缩事件、重开聊天与守护重启均保留气泡，实际本聊天丢失的 4 条手机请求已只读重放确认恢复，0 重复。桌面 21:14:36 的压缩后 replacement_history 不含最新手机请求的明文记录，最后普通 user 仍为旧设备问题；摘要有加密部分，不能断言全部请求信息丢失。随后回答旧问题，故当前跨任务接口仍有请求承接风险，增加提示语不能保证可靠，不宣称该风险已解决。没有改写 Codex 日志、重复投递或另开 writer。

原生通知同时解析 `dev_frame.d` 内实时 notify 与顶层离线补发 notify，保留字符串事件 ID 生成通知编号。先前只判断最外层 notify，导致手机在线时页面收到记录但没有系统提醒。Java 运行时测试覆盖完成、失败、提问、离线补发与无效消息；APK 编译、DEX、签名与实际 manifest 版本验证通过。锁屏声音、点击通知仍需真机确认。版本 1.2.7 / versionCode 15。此次修改仅修复消息展示和通知链路，不能保证转发接口的上下文承接与普通输入完全一致。
